## 一、背景与目标

`TestOps` 已有独立产品设计规范与整改基线，但与 Menusifu B 端统一规范仍存在细节缺口。本次目标不是复制商品中心业务规则，而是**抽取 B 端通用交互、布局、文案、表格、反馈等可复用规范**，映射到 TestOps 的测试用例工作台场景。

### 成功标准

1. `TestOps产品设计规范.md` 覆盖所有可借鉴的 B 端通用规范，并标注 TestOps 适配说明。
2. `TestOps设计整改基线文档.md` 新增对应整改项，研发可按 P0/P1/P2 排期。
3. 明确**不借鉴**项及原因，避免错误引入商品/菜单/价格等领域规则。

## 二、方案对比

| 方案 | 描述 | 优点 | 缺点 | 结论 |
|---|---|---|---|---|
| A. 全量合并 | 将 B 端规范全文复制进 TestOps | 覆盖最全 | 大量商品/菜单/价格/打印规则污染 TestOps；维护双文档 | 不推荐 |
| B. 增量补章（推荐） | 在现有 TestOps 规范中按章节增量补充缺失通用规则，并新增「B 端借鉴映射附录」 | 保持 TestOps 语境；可追溯来源；整改基线可同步 | 需人工做领域过滤 | **采用** |
| C. 仅更新基线 | 不改产品设计规范，只在整改基线写 checklist | 改动小 | 规范与基线脱节；产品/设计缺少统一口径 | 不推荐 |

**推荐方案 B**：以 TestOps 现有规范结构为主干，从 B 端规范中抽取通用层规则补入，并在附录建立映射表。

## 四、TestOps 领域映射

### 4.1 列表类型映射

| B 端列表类型 | TestOps 对应页面 | 默认字段顺序建议 |
|---|---|---|
| 主数据列表 | 项目列表、Skill 列表 | 名称 → 代号/类型 → 状态 → 统计 → 时间 → 操作 |
| 单据列表 | 生成任务列表、评审队列 | 时间 → 标识 → 状态 → 关联对象 → 操作 |
| 主数据详情明细 | 用例步骤表、测试数据表 | 序号 → 步骤/键 → 内容/值 → 操作 |

### 4.2 按钮命名映射（来自 B 端 4.5）

| 场景 | 统一命名 |
|---|---|
| 列表页创建 | `+ 新增` 或 `新建项目` / `新建用例`（带对象） |
| 表单提交 | `保存` / `保存修改` |
| 弹窗确认 | `确定` / `取消` |
| 列表行内 | 保留 2-3 个高频操作，其余收入「更多」 |
| 选择关联对象 | `选择`（不用「添加 XXX 分组」） |

### 4.3 删除提示模板（TestOps 版）

| 对象 | 中文模板 |
|---|---|
| 项目 | 确认归档项目「{name}」吗？归档后默认从进行中列表隐藏。 |
| 用例 | 确认删除用例「{title}」吗？删除后不可恢复。 |
| 文档 | 确认删除文档「{name}」吗？删除后将影响关联生成任务追溯。 |
| Skill | 确认删除技能「{name}」吗？ |
| 批量 | 确认删除选中的 {count} 条记录吗？ |

## 六、实施顺序建议

1. **规范文档更新**（本次交付）：统一产品/设计/研发口径。
2. **P0 整改**：筛选标签右对齐、表格对齐、删除/确认文案、查询轨迹。
3. **P1 整改**：分页条数记忆、列显隐记忆、导出命名、字体层级 CSS token。
4. **P2 整改**：快捷键、步骤条（若引入多步向导）、滚动条样式统一。

## 七、风险与例外

1. TestOps 部分页面已按现有规范实现第一阶段整改；新增 B 端规则与之冲突时，以更新后的 `TestOps产品设计规范.md` 为准。
2. 批量操作、列自定义、账号级偏好记忆依赖后端能力时，前端先统一交互与文案，记忆功能可分期落地。
3. Tabs 页签：B 端建议谨慎使用；TestOps 当前以侧栏 + 面包屑为主，不主动引入多页签工作台。
